Section 4

Why HMS work is slower per screen

ChamberQ greenfield velocity does not transfer 1:1 to hospital-grade modules.

  1. Financial correctness is an invariant problem, not a screen problem. A ledger needs reconciliation tests, not feature tests.
  2. Domain knowledge we do not have. How Chattogram diagnostic centres split referral-doctor commissions, and how BD hospital accounting conventions run, cannot be produced by AI. This is the single largest schedule risk — and it is exactly what the domain/QA hire retires.
  3. We now have live clients. Every HMS migration touches shared tables. Regression budget goes up; support competes for build hours.
  4. Data migration from whatever the client runs today.
  5. Module-by-module production shipping (the chosen model) adds per-module release, migration-on-live-DB, and pilot-support overhead — worth paying, but it is not free.

Section 7

Architectural decisions this plan forces

Expensive to change later. None is a blocker; all need an explicit call — log in decisions.md when chosen.

1. Ledgers, not mutable columns

Both the accounting ledger and the stock ledger must be append-only with balanced-entry invariants enforced at the single write path — the same "put the guard where the code converges" lesson from SMS segment billing (GsmText::toSingleSegment() inside SmsService::send()). Money and stock deserve the same choke point.

2. Shared-DB multi-tenancy at ~150 tables

We are at 45 migrations with 19 FKs into tenants (0000_01_01_000000, deliberately ahead of Laravel's own — do not renumber). HMS roughly triples that. Recommendation: stay shared-DB and invest in tenant-scope enforcement, because per-tenant databases would break ResearchDataService and SellerOverviewService.

3. Bangla staff panel

The 2026-08-08 decision made the admin panel English-only. Ward, store and pharmacy staff in Chattogram will need Bangla. That decision needs revisiting — extending PatientFacingBanglaTest discipline to the admin panel means hundreds of strings.

4. A real queue worker is now required

SendDoctorLateNotices uses ->afterResponse() because no worker runs. Stock revaluation, report generation and accounting period close cannot work that way. Infrastructure work — QueueTenancyBootstrapper is already enabled.

5. Clinical media has no off-server backup

Local disk; S3 is a one-line config change but nothing is backed up off the server yet. A system holding hospital records cannot ship in that state. Must be closed before phase 7 (IPD), ideally before phase 3.

6. Laravel 13

Not upgrading (per instruction). An 8-month build spans its release — write upgrade-clean code and avoid deprecated APIs so the option stays cheap.
