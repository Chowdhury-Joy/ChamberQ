1 — Product

What ChamberQ is

Real-life picture: a shopping mall with many shops. One building (this Laravel app, one shared database). Each doctor’s clinic is a shop. The mall also has a sales floor (ChamberQ marketing site), a mall-manager office (Super Admin), and a partner desk (marketers).

WhoWhat they useTypical URL
PatientDoctor website, book serial, ticket, outdoor TV, phone portal/{slug}/book or custom domain /book
Desk / doctorFilament admin: roster, live queue, consult pad, cashbook/{slug}/admin
Platform ownerCreate tenants, confirm bKash, marketers, backupscentral /admin
MarketerReferral link and commission listcentral /partner

Sellable pieces

  • Plan size: Maestro (solo chamber) vs Clinic (multi-doctor, extra public pages).
  • Product modules (checkboxes on the tenant, independent of size): Front door, Live queue, Prescription.
  • Opt-in extras: Stations (rooms + split till), Referrals (outside GP commissions), HR (attendance / leave / payroll).

Patients do not pay online. They take a serial; money is collected at the desk. Do not add a payment gateway unless the owner explicitly asks.

SMS is a prepaid wallet on the tenant. Empty wallet skips the text; the booking still succeeds.

2 — Locks

Do not change these unless the owner uses the unlock phrase

Patient homepage lock Do not edit resources/views/tenant/solo/webpage.blade.php or resources/views/tenant/solo/sections/**, and do not restyle or rewire homepage Book Appointment buttons. Unlock phrases: update patient homepage or change patient homepage. Book CTAs must keep tenant_safe_href(..., '/book') so path tenants hit /{tenant}/book, not bare /book.
Session expiry lock Staff stay signed in on purpose. Locked values: SESSION_LIFETIME=525600 (one year) in .env, .env.example, and the default in config/session.php (not Laravel’s 120). SESSION_EXPIRE_ON_CLOSE=false. AUTH_PASSWORD_TIMEOUT=31536000. Unlock phrases: change session expiry or restore session timeout. A security audit does not unlock this. Browsers cap cookies near 400 days; do not “fix” it to a huge number.
Still allowed without those phrases Booking wizard, ticket, portal, outdoor screen, Filament, CSRF, tenancy, session driver/path/domain, diagnosing sessions that drop early (that is a bug, not expiry).

3 — Tenancy

How a request finds the right clinic

This is the most important wiring in the project. Get it wrong and a patient books the wrong doctor, or Livewire posts land in the central shop.

HostHow the clinic is identifiedExample
Central (values in CENTRAL_DOMAINS)Path slug = tenant iddoctorgemini.com/drkarim/book
Doctor’s own domain (optional)Domain row on the tenantdrkarim.com/book (no slug)

Single shared MySQL database. Isolation is tenant_id on rows (BelongsToTenant), not a separate database per clinic. Stancl’s CreateDatabase / DropDatabase pipelines are deliberately empty in app/Providers/TenancyServiceProvider.php. Do not re-enable them — they cannot run on shared cPanel and would contradict this data model.

Boot order

  1. bootstrap/app.php — Laravel, routes/web.php, health /up, prepends InitializeTenancyForTenantHosts on the web group (covers Livewire /livewire/update).
  2. bootstrap/providers.php — Super Admin, Marketer, Tenant Admin (domain), Tenant Admin (path), Tenancy, AuthDebug.
  3. TenancyServiceProvider::mapRoutes() loads routes/tenant.php.
  4. routes/tenant.php registers the same public/API routes twice: path tenancy on the central host, domain tenancy on custom hosts. Path routes are registered first so /{slug} never swallows /{tenant}/book.
Reserved path prefixes config/tenancy.php blocks tenant slugs that would clash with admin, partner, find, me, assets, etc. Super Admin rejects those slugs at create time.

Helpers tenant_web_url() and tenant_safe_href() in app/helpers.php prefix same-origin paths on the central host. Use them. Hard-coded /book on a path tenant 404s or hits the wrong app.

8 — Connections

How journeys wire through files

Patient books a serial

Website Blade → BookingController GET /book (and POST /book flashes name/phone — never in the URL) → GET /api/bookings/open-dates + availability → GET /api/patients/by-phone (throttled 10/min, masked initials only) → POST /api/bookings → BookingService (transaction + lockForUpdate) → SendBookingConfirmation afterResponse → SmsService → ticket Blade → GET /api/queue/{uuid} poll

The wizard’s ticket_url is a relative path (tenant_web_route(..., absolute: false)) so it never navigates to a baked-in localhost host.

Waiting-room day

DailyRoster / LiveQueueControl → LiveSessionService (lock live session) → statuses: waiting → called → in_chamber → completed → ScreenController + screen Blade (TV) → ConsultScreen follows current_booking_id → VisitRecordService + Rx desk (if Prescription module) → SendQueueApproachPushes (Bangla copy; stage must rank higher than last_stage)

Prescription to the phone

ConsultScreen Save → Prescription rows → staff SMS via NotifySmsController (auth + belongsToCurrentTenant + doctor prefs) → GET /p/{token} (10-char, 48h, one SMS segment) → shared print sheet Voice/photo: doctor-only VisitMediaController — never on /p/{token} or portal

Portal backup: /portal/prescriptions/{id}?phone= — durable, phone must match. Optional PortalPrescriptionLock after the patient chooses a password. SMS token still opens today’s pad for 48h without that password. Reception can clear a forgotten password on Patients.

Onboard a doctor

Super Admin TenantResource create → TenantUserBootstrapService (owner / doctor / helper logins — one-shot passwords) → feature_flags (modules) → public site at /{slug}/ immediately

ChamberQ support uses the helper login; it is invisible on the owner’s Staff list. Never hand the helper password to the client.

Chamber internet drops

Queue runner keeps Call next on that computer (chamberq-queue-offline.js). Pad Save still works. Walk-ins / Mark Late / End session stay frozen. When the line returns, POST /api/offline/sync replays events in order; a conflict stops with “Refresh — the line moved elsewhere.”

9 — Hardening

How we made modules as battle-hardened as this stack allows

This is not “we tried to write clean code.” Each item below is a converging guard — a rule that used to live in someone’s memory and broke, then was moved to the place every request already passes. That is the house style. Prefer another guard at the same choke point over a comment or a wiki page.

Front door (website + booking)

  • Double-book race: BookingService creates inside a transaction and lockForUpdate() on the schedule/lab row (and doctor when needed). Two last-seat taps cannot both succeed. Verify this on MySQL; SQLite serialises writes and hides lock bugs.
  • Identity leak: public phone lookup returns masked initials + age only, throttled 10/min. Hero form POSTs name/phone into session instead of putting them in the query string.
  • Ticket is a secret: UUID + 60/min throttle. Queue poll uses the same secret.
  • Module off = 404 via middleware, not a hidden button. Disabled product must not be reachable by URL.
  • Billing closed blocks POST /api/bookings while still allowing ticket/portal reads.
  • CMS XSS: tenant HTML goes through sanitizers; hrefs through SafeUrl.
  • Locale phishing: /lang/{locale} only trusts same-host Referer. Off-site Referer is ignored.

Live queue (TV, Call next, pocket buzz)

  • Two staff Call next: LiveSessionService locks the live_sessions row first. Offline replay locks the same way and refuses if the line moved elsewhere.
  • SSRF on push subscribe: the ticket route is public, so a booking id is free. PushEndpoint allows only https, port 443, no userinfo, no private/reserved IPs, no localhost/.internal. Staff subscribe also requires tenant membership.
  • Push is not SMS: approach buzz is Web Push only. Copy is forced Bangla. Stage is monotonic so a stale phone is not re-buzzed for an older state. 410/404 deletes the subscription.
  • Missing VAPID: binds a null sender so the job no-ops; open-tab vibrate still works. Production check warns.
  • Ticket “ahead of you” counts only waiting/called/in_chamber — skipped serials do not inflate the number.

Prescription (consult pad, SMS copy)

  • Tenant membership on every clinical GET/POST, not just auth.
  • Media vs text: voice/photos never ride on /p/{token} or portal. Share links expire (48h). Token is short so the SMS stays one segment.
  • Timing vocabulary is closed (PrescriptionTiming) so print can render Bangla/English from keys, not free text.
  • Catalogue empty is a blocker on production-check. Migrations do not import CSVs; catalogues:load must run on a new server.
  • Indication “Why?” never pulls drug marketing copy from the catalogue.

SMS (all modules that text)

  • GsmText inside SmsService::send() — callers cannot forget. One credit = one network segment. Bangla names transliterate rather than vanish.
  • Wallet: debit with send; non-2xx refunds the credit. Gateway bodies are redacted before log/storage (aggregators echo API keys).
  • Booking never fails because SMS failed. Pref-off and empty wallet skip; they do not roll back the serial.
  • afterResponse so Fatima’s browser is not held for the HTTP timeout (which caused double Confirm taps).
  • Late-notice job re-reads the booking and skips if cancelled between click and send.

Money, stations, follow-ups

  • Cash and vouchers lock the booking/cash row. Morning count and follow-up SMS lock so cron cannot double-charge or double-text.
  • Stations intervention sittings are not public-bookable. Forgotten OT dates stay on Missed procedures — nothing auto-cancels a procedure silently.

Platform / tenancy / ops

  • Seeders refuse production. Restore defaults to dry-run and sits behind Dangerous.
  • Research aggregates use k-anonymity (minimum group 10). Seller overview counts usage, not clinical notes.
  • DateOnly cast — SQLite used to store 00:00:00 on DATE columns so where date = today missed rows.
  • CI MySQL job exists because three migrations were unrunnable for months on real MySQL.
  • SourceHygieneTest fails absolute developer paths (/Users/…) in shipped source, and env() outside config/.
  • app:production-check is a machine gate for quiet failures (debug on, mail=log, sms=log, localhost APP_URL).
What “battle-hardened” does not mean It does not mean PCI, a full pentest, or that backups are already running. It means: races are locked where two humans click, SMS cost cannot silently 3×, tenant A cannot read tenant B’s pad via a shared cookie, and production config failures are refused by a command rather than a runbook. Remaining gaps are listed in section 11 — do not hide them in a go-ahead.

10 — Go live

What you must check before giving go-ahead for actual production

Sign this off in writing. “Tests are green on my laptop” is not a go-ahead.

A. Machine gate (blockers)

On the production-shaped environment (MySQL, real .env):

php artisan app:production-check --strict

Must exit 0. That command currently refuses or warns on:

  • APP_DEBUG=true (stack traces to strangers)
  • APP_ENV not production
  • Missing APP_KEY
  • DB_CONNECTION=sqlite
  • APP_URL localhost or not https (SMS ticket links use this)
  • MAIL_MAILER log/array (password reset never arrives)
  • SMS enabled with driver log (serials never texted) — or set SMS_ENABLED=false deliberately
  • Empty medicines / conditions tables in production
  • Warnings: clinical media on local disk; session cookie not Secure; empty VAPID keys

With --strict, warnings fail the release too. Decide with the owner whether local-disk media is acceptable for week one; if yes, document the backup plan in the go-ahead, do not ignore the warning.

B. Database and data

  • MySQL 8 with utf8mb4. Migrations run clean on a fresh MySQL, not only SQLite.
  • php artisan catalogues:load after migrate. Spot-check a medicine search on Consult Screen.
  • Confirm php artisan test on MySQL (see architecture Getting Started / CI job). Report engine in the go-ahead.
  • Foreign keys, DATE columns, and a two-tab last-seat booking test on MySQL.
  • Backup story exists: Super Admin chamber ZIP + platform ZIP. Restore tested in dry-run on a copy, never first-try on live.
  • Clinical media disk is durable or the server disk is backed up on a schedule you can name.

C. HTTP, TLS, proxies

  • HTTPS everywhere. SESSION_SECURE_COOKIE=true.
  • TRUSTED_PROXIES set to the reverse-proxy IPs/CIDRs. Star is only safe if PHP is not reachable except through that proxy (bootstrap/app.php).
  • CENTRAL_DOMAINS is the real host(s), including www if used.
  • Custom doctor domains: DNS + TLS + domain row; book + admin both work at root.
  • Health check /up from the load balancer.
  • Branded error pages load; APIs still return JSON on error.

D. Mail, SMS, push — send a real one

  • Password reset to a real doctor inbox (not log).
  • One booking confirmation SMS to a real BD number; confirm one segment, wallet decremented by 1, ticket link opens on a phone (not localhost).
  • Doctor-late SMS and prescription-link SMS with prefs on/off.
  • If Live queue pocket buzz is sold: VAPID keys set; Allow on a ticket; lock the phone; Call next until two-away — notification fires.
  • If SMS is intentionally off for launch, SMS_ENABLED=false and the owner has accepted “no texts.”

E. Scheduler (cron)

Production must run Laravel’s scheduler every minute. Without it, marketer monthly commissions, follow-up reminders (07:00), and stations morning counts (09:05) never run.

* * * * * cd /path/to/app && php artisan schedule:run >> /dev/null 2>&1

There is still no queue worker requirement for booking SMS (afterResponse). Do not assume QUEUE_CONNECTION=database in .env.example means a worker is running.

F. Product walkthrough on the live tenant

Use a throwaway patient phone. Cover the modules that tenant actually bought:

  • Front door: home → book (open dates only) → ticket → portal by phone → Bangla switch.
  • Find + optional /me OTP if that surface is on.
  • Live queue: start sitting, Call next, Patient arrived, TV bookmark /screen/{session} (always today), skip, end session (WhatsApp for cancelled names).
  • Prescription: Consult Screen follows the called patient, save & print, /p/{token} on a phone, portal pad, voice/photo stay off the share link.
  • Desk jobs: a money-only staff login cannot Call next; a queue-only login cannot collect fee (if jobs were assigned).
  • Chamber scope: a staff stamped to chamber A does not see chamber B’s roster.
  • Disabled module URLs 404.
  • Helper login works for support; owner cannot see that user on Staff & Roles.

G. Security / privacy pass (go-ahead, not a full audit)

  • Doctor of tenant A cannot print tenant B’s prescription by swapping the slug (same cookie).
  • Public phone lookup never returns a full name.
  • Research page does not show tiny identifiable diagnosis groups.
  • AUTH_DEBUG=false in production (request logging includes session fragments).
  • No demo seeder run against production.
  • File permissions: storage/ and bootstrap/cache/ writable by the app user only.
  • php artisan config:cache / route:cache only after env is final; then re-run production-check.

H. Ops you must name in the go-ahead email

  • Who gets error logs / monitoring (none ships in-repo today — pick something).
  • How Super Admin confirms bKash (manual) and tops up SMS credits.
  • How a chamber backup is downloaded weekly until off-server backup exists.
  • Timezone APP_TIMEZONE=Asia/Dhaka — sitting “today” follows this.
  • PHP upload limits if voice notes are sold (local serve uses 20M in composer dev script).

11 — Gaps

Known outstanding production gaps (do not paper over)

As of the 2026-08-08 production-scope decision, these were still true unless ops has since closed them outside the repo. A go-ahead should say which are accepted for launch:

  1. Nothing is backed up automatically — neither MySQL nor clinical media on the local disk. In-app ZIP download exists; off-server schedule does not.
  2. SMS / mail default to log until env is switched. Never assume a staging send proves production credentials.
  3. No error monitoring product in the repo (no Sentry/Flare wiring required by default).
  4. No production deploy config in-repo (no Forge/Envoyer recipes). You bring nginx/php-fpm/cron.
  5. Patient portal can return bookings for a typed phone (by design, pay-at-chamber, no patient accounts required to book). Optional portal password only gates prescriptions after the patient sets one.
  6. Solo patient homepage still uses Tailwind CDN (locked UI — do not “fix” without unlock phrase).

13 — Working here

How to change code without breaking the product

  1. Read decisions.md, bug_history.md, architecture.md, sitemap.md before coding.
  2. If a request contradicts a logged decision, stop and ask. Do not silently override pay-at-chamber, homepage lock, or session lock.
  3. Run tests before you start and write down pre-existing failures. Report the delta at the end.
  4. New regression tests must be watched failing without the fix. Confirm the revert actually removed the fix (stash is a no-op on untracked files).
  5. Put guards where code converges (SmsService, BookingService locks, middleware), not in a comment.
  6. Do not restyle conversion layouts “while you are here.” CRO and chamber muscle-memory beat tidy CSS.
  7. If you add/delete/rename files under app/, routes/, config/, database/, resources/views/, or public/, update architecture.md and append architecture_history.md. Behaviour changes count even without new files.
  8. Route or journey changes → sitemap.md.
  9. Never rewrite old architecture_history.md lines; append a correction.
  10. Never edit a copy of AGENTS.md; edit ~/AGENTS.md if the protocol itself must change.

15 — Traps

Failures this codebase already had (do not repeat)

  • SMS “keep bodies ASCII” as a convention lasted two days — now GsmText inside send.
  • Date cast missed call sites — use DateOnly and search for new date columns.
  • SQLite hid unrunnable MySQL migrations and lock races.
  • Arbitrary Tailwind in Filament pages without Vite theme = unstyled layout.
  • env() in providers after config:cache made AUTH_DEBUG impossible to turn on in production.
  • Role-only auth on shared-host panels leaked across tenants.
  • Web Push url validation allowed SSRF to metadata/loopback.
  • Booking confirmation ran inside the patient request and looked like a failed book.
  • Absolute /Users/… paths in source — hygiene test now fails the build.

Full write-ups: bug_history.md. If you fix a bug, append there and fix the matching architecture.md bullet in the same task.
