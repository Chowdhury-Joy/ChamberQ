Section 1

Read this first

This is not a hospital HIS. It is a chamber product for Bangladesh solo doctors and small clinics. Patients book a serial online and pay at the desk. There is no patient login and no payment gateway.

Before any code change, read these four files in the repo root: decisions.md, bug_history.md, architecture.md, sitemap.md. The operating protocol is AGENTS.md (symlink to ~/AGENTS.md). Do not edit a copy of those rules.

What the product does

Each paying doctor (a tenant) gets a branded website, online serial booking, a live waiting-room queue with outdoor TV, and a digital prescription pad. Super Admin creates tenants by hand after a WhatsApp sales chat. Marketers earn commission on setup and monthly fees (manual bKash). SMS is a prepaid wallet, not included in the plan.

Three product modules (à la carte for Solo / Maestro)

All three together is the Maestro bundle (internal plan key stays solo). Clinic tier still uses Clinic list price. Modules default on when the flag is absent so existing chambers keep the full product. Routes use tenant.module:{name} middleware (EnsureTenantHasModule).

Do not build online patient payment unless the owner explicitly asks. Pay-at-chamber is a logged decision (27 Jul, restated 31 Jul). Do not “restore a sane session timeout.” Do not restyle the solo patient homepage. Unlock phrases are in Section 6.

Section 2

How to run it

PHP 8.3+, Composer, Node. Local DB is SQLite. Production DB is MySQL — CI runs both. Do not drop the MySQL job to speed CI.

Setup

composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite
php artisan migrate --seed
php artisan catalogues:load   # required — ~24k medicines + conditions (~12s)
npm install && npm run build
php artisan serve
Migrations leave catalogues empty. Forgetting catalogues:load makes prescription pickers blank with no error. app:production-check treats an empty medicines or conditions table as a blocker. CI runs the load before the readiness gate.

Optional custom domain in local: http://solo.localhost/ (root paths, no slug). Production uses the doctor’s own domain the same way.

Tests

php artisan test (SQLite in-memory). MySQL: create soldoc_mysql_test, then DB_CONNECTION=mysql DB_DATABASE=soldoc_mysql_test … php artisan test. Shell env overrides .env and phpunit.xml. GitHub Actions: .github/workflows/tests.yml — SQLite job + phpunit-mysql on MySQL 8.4.

Tenancy (the thing that bites)

  • Path tenancy on the central host: /{tenant}/… (e.g. /drkarim/book).
  • Domain tenancy for optional custom domains: routes at root (/book, /admin).
  • Never use stancl’s tenant_route() for patient links. Use tenant_web_url() / tenant_web_route() / tenant_safe_href() / TenancyUrl::publicAbsolute().
  • Outbound links (SMS, WhatsApp, ticket Copy, TV bookmark) must go through TenancyUrl::publicAbsolute() or they bake localhost. Same-origin polls stay relative.
  • All three Filament panels share one session cookie on one host. Role checks are not enough — tenant-owned clinical routes also check User::belongsToCurrentTenant().

Section 3

Architecture snapshot

Single shared database, tenant-scoped rows. Live truth is architecture.md — this page is the map, not a substitute.

Stack

PHP ^8.3 (Composer platform.php = 8.3.0 — match the live host, not a newer laptop). Laravel 12, Filament 4, Livewire, stancl/tenancy 3.10, Vite 7, Tailwind 4, PHPUnit 11. Filament HTML sanitiser pinned to Symfony 7 (8.x needs PHP 8.4).

Write paths (do not bypass)

JobSingle write pathWhy it matters
Create a bookingBookingServiceRow lock, serials, capacity, patient resolve, duplicate-person guard. Wizard, roster walk-in, and queue walk-in all go here.
Queue mutationsLiveSessionServiceEvery mutation is DB::transaction + lockForUpdate() on the session. Roster and Live Queue Control share this so the TV and ticket stay in sync.
Visit notes / RxVisitRecordService::saveForCompletedBooking()Desktop pad, phone modal, and Complete visit all land here. Empty form creates no row.
Staff paper RxVisitRecordService::saveStaffEnteredPrescription()Whitelist of fields. Cannot inject diagnosis/vitals. Off by default per doctor.
Cancel a dateSlotBlockServiceOnly path. Completes in-chamber patients; cancels waiting/called/skipped.
SMSSmsService::send()Every body goes through GsmText::toSingleSegment(). Debit before send, refund on hard failure. Never use __() in SMS bodies.
Doctor’s shortlistMedicineService::saveDoctorMedicine()Only from My medicines or the ★ on the desk. Prescribing does not “learn.”

Key screens (tenant admin)

  • Daily Roster — day’s list, walk-ins, Mark Late, Mark Completed. When live queue is off: Arrived / Done / No-show.
  • Live Queue Control — start sitting, Call next, arrived, skip, pause, end. Outdoor TV bookmark (date-free /screen/{session}). Catch-up banner for notes not written.
  • Consult Screen — auto-follows current_booking_id. ≥1024px + in-chamber = full Rx desk. Phones keep the modal. Complete visit then Call next are two steps.
  • My medicines — doctor-curated defaults + Rx packs. Packs are created here, applied on the desk.
  • Follow-up reminders — WhatsApp confirm queue. SMS auto-sends 3 days before (daily 07:00).

Roles

Central: Super Admin, Marketer. Tenant: admin (full, but not the queue runner by default), doctor, staff. Queue is doctor or staff only — never the account-owner admin unless they also have that role. Consult Screen and visit notes are doctor-only, except staff paper-entry when that doctor opted in.

Prescription pad — current behaviour

Desktop Consult Screen is a BD pad: left clinical (C/C rows, H/O chips seeded from the patient file, O/E vitals with last-visit grey reference, Dx, Inv), right medicine table. Prefill is doctor saved default → catalogue default → blank, field by field. Vitals are never pre-filled. Packs apply but never wipe existing rows. Safety warnings never block save. The disclaimer must appear beside every warning (desk + modal) — RxSafetyTest fails if either drops it.

Print and patient copy share one Blade sheet. Patient copy is the full clinical pad (no voice/photo). Share: /p/{token} (48h) plus durable portal backup gated by phone.

Section 5

Journeys you must not break

Full map: sitemap.md. If you add/remove a route or change a CTA, update that file in the same task.

Patient

  1. Open tenant home (or custom domain) → Book.
  2. Wizard: chamber/doctor if needed → When can you come? (only dates with seats, 60-day window) → name / phone / optional NID / optional other WhatsApp / share-history checkbox.
  3. Household on a known phone: masked initials only (F. R., 34), never full names on the public API.
  4. Ticket UUID. Share WhatsApp / copy / print. Live queue poll if that module is on.
  5. Later: /portal by phone — bookings + up to 2 recent prescriptions.
  6. Waiting room: staff bookmark /screen/{session} once (always today).

Sitting day

  1. Queue runner (staff or doctor per Branding) opens Live Queue Control → Start → Call → Patient arrived → doctor writes on Consult Screen.
  2. Doctor: Complete visit (patient stays on screen for print/WhatsApp) → Call next.
  3. Mark Late (roster or queue) texts waiting patients if that doctor’s late SMS is on — after-response job, not inline, because there is no queue worker.
  4. End session / doctor absent: in-chamber patient is completed, not cancelled; staff get a tell-cancelled-patients hand-off.

Sales / Super Admin

No self-signup. WhatsApp CTA → Super Admin creates tenant (slug, modules, marketer, discount, doctor login email required) → confirm bKash → commissions move pending → owed → paid. Client Health is counts only — never patient names or diagnoses. Research is coded-diagnosis aggregates with k-anonymity (min group 10).

  • Behavioural changes are architecture changes even with no new files.
  • Never rewrite past architecture_history.md entries. Append a correction.
  • Verify claims with git log -S and by reading the file. Do not copy unverified audit summaries into the log.

Traps (do not reintroduce)

  • SQLite is not proof. Three migrations were unrunnable on MySQL (tenants table order, composite FKs, SET NULL on composite keys). Always think MySQL.
  • Date columns: use DateOnly cast and plain where(), not whereDate() — the function kills the booking indexes and SQLite stores a time component.
  • SMS segments: one non-GSM character (em dash) turned a 1-credit message into 3. Guard is in GsmText inside send(), not a comment.
  • Patient merge must move visit_records and prescriptions via repointPatientOwnedRows(). Moving only bookings NULLed clinical history.
  • Filament bulk delete authorizes deleteAny(), not delete(). Policies that omit it allow the bulk action. Chambers/Doctors have no bulk delete.
  • This panel has no Tailwind on Live Queue Control — use scoped plain CSS (lqc-). Arbitrary utilities are silently dropped.
  • There is no queue worker. Jobs that must run today use ->afterResponse() (doctor-late SMS). A queued job would never send.
  • Medicine search must not hydrate the whole 24k catalogue. Path is MedicineService::search() only.
  • Dose chips come from the catalogue for that brand, never a hardcoded 500/10/20/40/5 mg list.

Deferred on purpose

  • Voice transcription — code stashed in docs/deferred/voice-transcription/. Do not reload it.
  • Handwriting OCR on prescription photos.
  • Licensed US drug-interaction database. Coverage report: 3.7% of real BD medicines have no US vocabulary entry. Shipped checker is a short curated list + disclaimer.
First week on the repo: run setup, book a serial on /solo/book, start a sitting, write a prescription on Consult Screen at desktop width, print it, open the patient copy. Then read bug_history.md end to end before touching queue, SMS, or tenancy URLs.
