# Architecture Overview
Last Updated: 2026-08-20T19:22:46+0600

## Overview
ChamberQ (product formerly "Doctor Gemini") is a multi-tenant SaaS for Bangladesh solo doctors and clinics. Each tenant can be sold **à la carte product modules** on top of a Solo/Clinic size tier: **Front door** (branded website + online serial booking + day list), **Live queue** (outdoor TV + Call next + ticket come-around), and **Prescription** (consult pad / digital Rx). Those three default on for existing chambers. Super Admin can also tick **Stations**, **Referrals**, **HR**, and **Pharmacy** — those stay **off** until ticked. Patients book a serial and pay at the chamber — there is no payment gateway. Online pre-payment is later-stage only: do not suggest or build it unless the owner explicitly asks. **Two booking doors:** the doctor's own website (name + phone, no account) and optional ChamberQ **Find a doctor** (`/find`) plus phone-OTP **Patient login** (`/me`) for one locker of serials and history across every Front door clinic. Sales CTAs on the central marketing site use WhatsApp (`wa.me`). Patient outbound notices (booking confirmation, doctor late, cancellation, after-visit share, follow-up) follow each doctor's `notify_channels` mix of **Auto SMS** (ChamberQ texts them from prepaid credit), **Push SMS** (staff tap Send SMS, still prepaid), and/or **Push WhatsApp** (staff tap `wa.me`, never auto); Super Admin tops up the tenant SMS wallet. Marketer partners and medical representatives earn commissions on the **paying** amount (manual bKash billing); Super Admin confirms doctor payments and partner payouts. Year 1 month-by-month is not commissionable unless a year is prepaid; year 2+ is a residual.

## Getting Started
Prerequisites: PHP 8.3+, Composer, Node/npm (for Vite assets), SQLite (local) or MySQL/Postgres (production). `composer.json` pins `config.platform.php` to `8.3.0` so dependency resolution matches the live host even when a developer laptop runs a newer PHP.

```bash
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite   # if using sqlite
php artisan migrate --seed
php artisan catalogues:load   # required — migrations create empty tables; this imports ~24,491 medicine SKUs + ~244 conditions (takes ~12s)
npm install
npm run build
php artisan serve
```

Optional: `composer run dev` (server + queue + Vite + logs).

Key environment variables (names only): `APP_KEY`, `APP_URL`, `APP_TIMEZONE`, `CENTRAL_DOMAINS`, `TRUSTED_PROXIES`, `DB_*`, `MAIL_*`, `MARKETING_WHATSAPP`, `MARKETING_PHONE`, `MARKETING_SOLO_*`, `MARKETING_CLINIC_*`, `MARKETING_SMS_CREDIT_PRICE`, `SMS_DRIVER`, `SMS_ENABLED`, `SMS_HTTP_URL`, `SMS_HTTP_API_KEY`, `SMS_HTTP_SENDER`, `VAPID_PUBLIC_KEY`, `VAPID_PRIVATE_KEY`, `VAPID_SUBJECT`.

Production must set `APP_URL=https://…` (not localhost — path-tenant SMS/outbound links are built from it) and `CENTRAL_DOMAINS` to the real public host(s). Patient-facing absolute links that leave the browser (SMS, WhatsApp, TV bookmark, ticket Copy link) go through `TenancyUrl::publicAbsolute()` (Domain or `APP_URL`). Same-origin navigation and polls use relative paths / `public_asset()`. `bootstrap/app.php` trusts reverse proxies via `config('app.trusted_proxies')` (`TRUSTED_PROXIES` env); `*` is fine locally, but production-check warns when it stays `*` because any client could spoof `X-Forwarded-For` and bypass IP throttles.


Shell environment variables override both `.env` and the `<env>` entries in `phpunit.xml`, so no config edit is needed. CI (`.github/workflows/tests.yml`) runs both engines on every pull request.

Before serving real patients, run the readiness gate as the last step of a deploy — a non-zero exit should stop the release:

```bash
php artisan app:production-check --strict
bash scripts/deploy.sh
```

`scripts/deploy.sh` runs migrate, `catalogues:load`, asset build, config/route/view cache, then the strict production gate. It does **not** configure the server — developers still set `.env`, cron (`schedule:run` every minute), reverse proxy TLS, off-server backup copies from `storage/app/backup-temp/`, and real SMS/mail credentials.

It checks the settings that fail *silently*: debug mode exposing stack traces, `MAIL_MAILER=log` swallowing a locked-out doctor's password reset, `SMS_DRIVER=log` meaning no patient is ever told their serial, still running on SQLite, a non-https or localhost `APP_URL` (patient ticket links in SMS are built from it), localhost in `CENTRAL_DOMAINS`, `AUTH_DEBUG=true`, `TRUSTED_PROXIES=*` on a production host (IP throttles can be spoofed), verbose `LOG_LEVEL`, clinical media on the server's own disk, an insecure session cookie, and empty VAPID keys (pocket buzz on a locked phone will not fire; the open ticket can still vibrate). Blockers exit non-zero; storage, cookie, VAPID, log level, and trusted-proxy items are warnings unless `--strict`. Defined in `app/Support/ProductionReadiness.php`, and CI asserts the gate can still pass on a production-shaped config so it cannot drift into something nobody can satisfy.

### Production go-live checklist (developer decisions)

These cannot be chosen by code alone — the owner picks vendors and credentials; developers wire them on the server:

| Area | What to set | Why it matters |
|------|-------------|----------------|
| **Host + TLS** | nginx/caddy → PHP-FPM, HTTPS cert | Patient pages and admin over plain HTTP leak session cookies |
| **Database** | MySQL 8, nightly off-server dump | SQLite is dev-only; chamber data must survive disk loss |
| **`.env`** | See `.env.example` production block | Wrong `APP_URL` breaks SMS ticket links |
| **Catalogues** | `php artisan catalogues:load` after every migrate | Empty medicine/condition tables silently break Rx |
| **SMS** | `SMS_DRIVER=http` + gateway keys, or disable deliberately | Default `log` never texts patients their serial |
| **Mail** | Real SMTP/SES for password reset | Default `log` never reaches a locked-out doctor |
| **Backups** | Cron `schedule:run` + copy `storage/app/backup-temp/` weekly ZIPs | Platform backup runs Sunday 02:30; ZIPs still on-server until copied |
| **Clinical media** | `FILESYSTEM_DISK=s3` (or backed-up disk) | Voice notes and Rx photos are irreplaceable |
| **Monitoring** | `LOG_SLACK_WEBHOOK_URL` or host APM | No bundled Sentry — pick one channel and wire it |
| **VAPID** | Generate keys for pocket buzz | Optional but needed for locked-phone queue alerts |

**Locked product decisions** (need owner phrases, not developer choice): session idle expiry (`change session expiry`), patient homepage UI (`update patient homepage`), online payment (explicit owner ask).

Scheduled tasks: `commissions:generate-monthly` runs on the 7th of each month (pending monthly commission rows for referred active tenants). `follow-ups:send-reminders` runs daily at 07:00. `stations:morning-count` runs daily at 09:05 for tenants with the **Stations** module (visit vs intervention waiting counts pinged to doctors/admins via Filament database notifications).

## Tech Stack
- PHP ^8.3 (Composer `platform.php` = `8.3.0`), Laravel ^12, Filament ^4
- stancl/tenancy ^3.10 — hybrid tenancy: **path** on central domain (`/{tenant}/…`), **domain** for optional custom domains (root paths)
- mews/purifier ^3.4 (HTML sanitization for page builder); Filament uses `symfony/html-sanitizer` **^7.0** (not 8.x — 8.x needs PHP 8.4 `Dom\HTMLDocument`)
- Livewire (via Filament)
- Blade views for patient site, booking wizard, ticket, portal, waiting-room screen
- Vite ^7 + Tailwind CSS ^4 (front-end build)
- PHPUnit ^11 for feature tests
- SQLite locally and in CI; **MySQL in production — validated 2026-08-08**, and CI now runs the whole suite against MySQL 8.4 as well (`phpunit-mysql` job). SQLite alone had hidden three unrunnable migrations: it does not resolve foreign-key targets at CREATE time, has no `ONLY_FULL_GROUP_BY`, accepts a datetime in a date column, and serialises every write so row locks are never contended
- SMS: `log` driver (default) or `http` JSON POST gateway; prepaid wallet on `tenants.sms_balance`. A non-2xx reply throws so the credit is refunded, and `HttpSmsGateway::redact()` strips the configured `api_key` / `sender` out of the gateway's body first — that string is stored in `sms_messages.error` and logged, and aggregators routinely echo the request back ("invalid api_key: …")
- Web Push: `minishlink/web-push` ^9 with VAPID keys (`config/webpush.php`) for pocket buzz on the patient ticket — not SMS, not WhatsApp

Both no-op under PHPUnit regardless (`Log::spy()` swaps the log manager for a mock whose `channel()` returns null)
- `app/Support/GsmText.php` — keeps an SMS body inside one billable segment. Networks bill per **segment** (160 GSM-alphabet characters, or only 70 the moment one character falls outside it) while credits are sold as "1 credit = 1 message". `toSingleSegment()` transliterates via `Str::ascii()` — flattening typographic dashes and rendering a Bangla patient name readably (`ফাতিমা রহমান` → `fatima rhman`) rather than deleting it — then truncates prose, never a link, to fit. `segments()` is encoding-aware (160/153 GSM, 70/67 UCS-2) so the wallet can charge what was really sent
- `app/Jobs/SendBookingConfirmation.php` — texts a patient their serial, dispatched from `BookingService::createBookingForBookable()` with `->afterResponse()`. Same no-worker reasoning as `SendDoctorLateNotices` below: **not** onto the queue, or no patient would ever be told. Previously this ran inline in the patient's own request, so a booking that had already committed still held Fatima's screen for up to `sms.http.timeout` seconds — the moment she is least sure it worked, and the one that produces a second tap on Confirm. Re-reads the booking and **skips a serial cancelled between the response and the job running**. Swallows and logs a throwing gateway so an outage cannot surface as a 500 on a booking that succeeded. The wallet debit moves with the send, which is correct: a credit is spent when a message is attempted, not when a row is written
- `app/Jobs/SendDoctorLateNotices.php` — texts every waiting patient that the doctor is running late. Dispatched from `LiveSessionService::markDelay()` with `->afterResponse()`, **deliberately not onto the queue**: this application runs no queue worker, so a queued job would never be delivered and nobody would notice the patients went untold. After-response runs in the same process once the response is sent, needs no infrastructure, and still frees the screen. Carries `tenantId` and re-initialises tenancy itself, and is `ShouldQueue`, so moving to a real worker later is deleting `->afterResponse()` (`QueueTenancyBootstrapper` is already enabled)
- `app/Jobs/SendSessionCancellationNotices.php` — texts remaining patients when a sitting is finished early or marked absent, **only if that doctor's Cancellation Auto SMS is on** (off by default). Same after-response / no-worker shape as `SendDoctorLateNotices`. Vacation slot-blocks stay staff-tapped Push SMS. WhatsApp stays tap-to-send.
- `app/Jobs/SendVisitShareNotice.php` — after Complete visit, Auto-SMS the prescription share and/or Google review when that doctor's After visit **Auto SMS** is on. Same after-response / no-worker shape. Push SMS / Push WhatsApp stay desk taps.

- **Interaction-check feasibility** — measured 2026-08-12 with `drugs:coverage-report`, and the result gates the feature rather than describing one that exists. **There is no interaction checking in ChamberQ.** Of 24,486 catalogue rows, **92.9% are fully checkable** (every ingredient resolves), 1.6% partly, 5.5% not at all. Of what fails, 1,190 rows are devices, supplements and ORS that cannot interact anyway; **906 rows (3.7%) are real medicines absent from the US vocabulary entirely** — `doxophylline`, `rupatadine`, `bilastine`, `mirogabalin`, `roxadustat`, `cilnidipine`, `favipiravir`, `dexibuprofen`, `omarigliptin`. That blind spot is structural, not a data-cleaning task: any US-derived interaction database will under-warn on exactly the drugs that distinguish this market. Consequence for any future build — the screen must state which medicines it could **not** check, because a silent skip converts "no warning" into false reassurance.

## Data Flow
1. **Sales:** Visitor hits central `/` (`MarketingController`, optional `?ref=` / `?code=`) → WhatsApp CTA includes referral context → Super Admin creates tenant (Plan Tier Maestro, billing trial, SMS 0, all modules on, theme/locale already filled — slug + doctor login email are the required type-ins), ticks Prescription free for life if honouring it, types a paying price if this doctor gets a courtesy, attaches marketer and optional medical representative, reads the labeled list → paying → cuts preview → pending setup commission per payee.
2. **Billing:** Super Admin confirms doctor setup/monthly payment (manual bKash), or **Confirm 12 months prepaid** for a year in one action → setup/year lumps move to `owed` on amount paid (year 1 months have no partner cut unless prepaid as a year) → monthly cron creates pending year-2+ rows → Super Admin marks marketer/MR payout paid. **Client Health** (`/admin/seller-overview`) surfaces who went quiet, where new signups stall, SMS wallets at risk, and overdue accounts — counts only, never patient clinical data; clinic names open tenant edit. **Research data** (`/admin/research`) shows anonymous coded-diagnosis aggregates across all practices with k-anonymity (minimum group size 10). Super Admin dashboard is finance → platform totals → latest 8 tenants (Maestro/Clinic labels). Restore/Delete on tenant edit sit behind **Dangerous**; platform restore starts as a dry run.
3. **Patient book (doctor's website):** Tenant site → the clinic hero form **POSTs** to `/book` (phone then name flashed to the session, then redirected — never in the URL). `POST /` on a clinic host is the same `BookingController::prefill()` handler so a browser that posts the homepage does not 405; it still redirects to `/book` and does not render the homepage. ChamberQ marketing `POST /` is not a booking (custom-domain tenancy refuses it). The card order is centre (when needed) → phone → name → doctor → date/session. On a **multi-branch** clinic the card asks **Which centre?** first; **Select date** / **Select session** stay empty until chosen (no native calendar — those paint today as if it were already booked). Date and sitting lists then only that room’s **publicly bookable** sittings (`visit` / leftover `consult` — not intervention or counseling). A sitting from another centre is dropped server-side. Or a plain `GET /book` → wizard (chamber/doctor filters when needed, then **When can you come?** via `GET /api/bookings/open-dates` — only open dates with seats, soonest first; short identity step (summary strip, then details; **Change date** on the summary strip (or Back))) → `GET /api/bookings/availability` (re-check before submit) + `GET /api/patients/by-phone` (public, throttled 10/min, masked initials only) → `POST /api/bookings` (optional `patient_id`, `share_clinical_history` 0/1 defaulting on, optional `nid`, optional `year_of_birth`; leftover `age` is converted to a birth year once; optional `wants_earlier_date` still accepted by the API but not collected in the wizard; **refuses** intervention/counseling sittings — only `visit` and leftover `consult`) → `BookingService` creates booking + patient link inside a DB transaction with `lockForUpdate()` on the bookable (and doctor row when `slot_cap_mode` is `per_doctor_chamber`) → after commit, `SendBookingConfirmation` Auto-SMS the serial when that doctor's booking Auto SMS is on (SMS ticket link from `APP_URL` / custom Domain) → JSON `ticket_url` is a **relative** path so the wizard redirects without baking in a wrong host → ticket (share via WhatsApp/copy, or Print / Save as PDF via the browser print dialog). Staff may still follow up on any legacy `wants_earlier_date` rows from **Waiting for earlier date**. A ChamberQ patient login on the same host prefills name/phone; booking still does not require it.
3b. **Patient book (ChamberQ Find):** Central `/find` (public directory) → Book serial on `/{tenant}/book` (same `BookingService`) → ticket on that doctor's site. Optional `/me/login` (phone OTP) unlocks `/me` (upcoming serials across clinics) and `/me/history` (own visits + prescriptions, no share-flag gate, no media).
3c. **Staff book (Operations → Book serial):** Desk or call-centre staff pick the **doctor** first, then **visit type** (Usual / Follow-up / Intervention / Lab), centre when that doctor sits in more than one place, then a calendar of **only that doctor’s sitting days**, then sitting (lab type first when Lab). Same `BookingService` (`allowOverflow` false, confirmation SMS, `whatsapp_phone` when ticked, `forcedCarePath` for Usual vs Follow-up). A confirmation modal shows the serial, Push WhatsApp / Push SMS when those are on, and ticket. Daily Roster / Live Queue **New Walk-In** uses the same visit types, today only, with overflow stools; Follow-up stamps the paper-file mark. Live Queue walk-in is already on the open sitting (visit → Usual/Follow-up; OT → Intervention type; MSK → Lab).
4. **Clinic day:** **Start of day — Daily Roster** (who is booked that day — date picker, default today; **New Walk-In**, **Mark Late**, waiting **Outdoor vitals** when Stations is on stay on today). **During sitting — Live Queue Control** → start session → call patients → Patient arrived (`in_chamber`) → complete (doctors get optional visit-notes modal with voice/photo; staff complete without notes) → **Collect fee** on the current card when still Due (unless Branding **Collect fee at check-in** took it at arrival). Patients can also be called out of turn from their table row, and a no-response skip is taken from the current-call card with its consequence spelled out on the button. Doctor Consult Screen auto-follows `current_booking_id` for clinical context including last visit notes. Live Queue Control shows an amber catch-up banner when completed patients lack notes (**Fill in now**). End session names how many patients it is about to cancel and who, then hands staff a WhatsApp link per cancelled patient; it also warns doctors if notes are still missing and points them at **Fill in now** on the same page. **End of day — Daily Roster** again for leftovers (unpaid fee, missed vitals, unfinished rows). Row actions on both lists use **`DeskActionLayout`** (max two primaries + **More**). A doctor only sees Daily Roster when this practice has no staff login; call/complete/Mark Late actions only for the queue runner. End-of-day money is also **Operations → Cashbook** (income, expense, net, waived). For a doctor who prescribes on paper and has switched `staff_may_enter_prescriptions` on, staff get **Enter prescription** under **More** on that doctor's *completed* roster rows: they photograph the slip, type the medicines and follow-up, and the visit gains a prescription with no status change and no doctor approval step — staff still see no diagnosis, voice note or visit history. Both screens route through `LiveSessionService`, so outdoor screen and ticket stay in sync. Outdoor TV polls `/api/screen/{session}` (always today) with an HMAC `?token=` from the page HTML; a Stations clinic can instead bookmark `/screen/chamber/{chamber}` which polls `/api/screen/chamber/{chamber}` for every live room — same token gate. Ticket page polls `/api/queue/{booking}` — neither exposes visit notes or media paths. Calling next also dispatches pocket-buzz Web Push for subscribed tickets (two away / next / called); **not SMS, not WhatsApp**. Staff still only tap Call next.
4a. **Stations pathway (module on):** Patient books a **visit** sitting (paid, public wizard) → staff/doctor **Send to lab** (type, today MSK) and/or **Send to intervention** onto an OT sitting, picking the procedure type from the fee catalogue when rows exist (PRP, epidural, …; stored on `bookings.fee_catalog_item_id`) (paid, not public; SMS off for next-day — staff tell them) → **Mark prepped** → **Call doctor** → **Procedure done** → **Send to counseling** (free same-day row, no voucher). A forgotten OT date stays on **Operations → Missed procedures** until staff WhatsApp or **Move**. Nothing auto-cancels.
4b. **Pharmacy counter (module on):** Super Admin ticks **Pharmacy**. Desk with the Money job (or owner) adds shop SKUs and receives boxes (pay ৳0 / some / full now), then opens **Operations → Pharmacy**, sells from today’s Rx or a walk-in (optional name, no phone — this is a shop sale, not a serial), takes cash/bKash at the counter (patient pays sell price; cashbook income is that full amount). The printer opens an A4 portrait **MEDICINE VOUCHER** (`GET /pharmacy-sales/{sale}/invoice`) that matches the paper pad — one A4 page, checkered border, Branding logo (no clinic-name text), Cash/Online ticks, sequential Sl No, lines, amount in words. The till list shows **Amount**, the medicine names (**Type of medicine**), and **Return** (same-day undo — not supplier **Return unsold**). Live qty drops. Optional doctor % of profit only when the sale is tied to a prescription. **Physical count** and **Pay supplier** are hidden for now (services still exist). Same-day Return undoes the sale. Solo stays prescribe-only until the tick is on.
5. **Writing the prescription (desktop, mid-consult):** Doctor opens the Rx pad → C/C as complaint rows (each with its own duration), H/O already seeded from the patient record, vitals typed fresh (including Temp °F) with last visit's shown grey beside them → finding chips write into Other findings → picks a diagnosis, which offers his own packs for it, Add investigations under Diagnosis, and advice chips plus a starter-advice chip in the Advice box (tap to copy; a save does not hide it) → types a brand, and the row's dose, frequency, duration and timing arrive already resolved through his own saved default, then the catalogue's, then blank → types into **Why?** and a list suggests (Fever from a curated list; diagnoses from the condition catalogue after three letters — never the drug's marketing text) → ★ saves that line to **My medicines** (packs themselves are built there, not here) → drag or ↑↓ to order the medicines → **Save & print** posts once via `ConsultScreen::saveRxDesk()` → `VisitRecordService::saveForCompletedBooking()` without ending the visit. Optional **My paper** tick (this browser only) prints onto the doctor's own pads by hiding the ChamberQ letterhead. Every one of those fills is a proposal on a document the doctor signs: visible, editable, and cleared in a keystroke.
6. **Lookup:** Patient opens `/portal`, **POST**s phone (not GET — the number must not sit in the URL/history/logs) → session stores it; booking list (throttled) **and** prescriptions with medicines, newest first. After a completed visit they may **optionally** set a password (`PortalPrescriptionLock`, min 6 characters, SMS OTP via `PortalOtpService` before set/unlock, per-phone unlock rate limit after five wrong tries); until they choose one, pads stay phone-only. If they set one, later visits need OTP + password unlock for the session. SMS `/p/{token}` still works 48h without it. Consult Screen and cross-chamber shared history never use this password. Fully translated for Bangla, as are the wizard and ticket — `PatientFacingBanglaTest` fails the build if a patient-reachable string has no `lang/bn.json` entry. Tenant admin **reading copy** (Live Queue stats, roster columns, dashboard widgets, sitting notes) follows `tenant.default_locale` via `__()` (`StaffDeskBanglaTest`). Sidebar, page titles, and buttons stay English; `EnglishFilamentLoader` keeps Filament vendor chrome English even when locale is `bn`. Super Admin and Marketer stay English.
7. **Content:** Admin structures WebPages; staff edits text/images; public `/{slug?}` renders tenant site. Search engines read title/description/canonical/JSON-LD from `PublicSeo` and the XML sitemap; they are told not to index tickets, portal, TV, or `/me`.
8. **Labs (clinic tier / flag):** Patient can add lab tests + collection slot during booking; ops manage LabTests + LabCollectionSlots in admin.
9. **Chamber outage:** Queue runner on Live Queue Control (or the same machine driving the TV) → line drops → yellow banner (“Call next still works on this computer”) → Call next / arrived / skip / complete-without-advance queue locally (`chamberq-queue-offline.js`) and update the outdoor screen on that device → pad Save/Print still work (`rx_save`) → walk-ins / Mark Late / End session stay frozen → when the line returns, `POST /api/offline/sync` replays queue events in order (conflict stops with “Refresh — the line moved elsewhere”) and uploads pad notes.
10. **Visiting / camp day:** Night before, doctor taps **Pack bag** on **Operations → Visiting / camp** → at the remote room they add walk-ins and print from the laptop → pending `visiting_visit` items upload when signal returns (SMS only after that).

## Integrations
- **stancl/tenancy** — central path (`InitializeTenancyByPath`) + custom domain (`InitializeTenancyByDomain`); shared DB; `config/tenancy.php` `reserved_path_prefixes` protects `/admin`, `/partner`, `/find`, `/me`, `/robots.txt`, `/sitemap.xml`, assets, etc. Cache tenancy is `App\Tenancy\CacheTenancyBootstrapper` (not Stancl's tagged-only bootstrapper) so the default `CACHE_STORE=database` can run inside a chamber.
- **Filament 4** — Super Admin + Marketer + Tenant Admin panels
- **WhatsApp** — outbound only via free `wa.me` links (no Business API): cancellation notices, doctor-late hand-off, and prescription share links when that doctor's stage WhatsApp toggle is on — always tapped by a human, never automated. **Not used** for “you’re next / come back from tea” — that is Web Push + the open ticket.
- **Web Push** — `minishlink/web-push` to the browser (typically FCM on Android Chrome). VAPID keys in `VAPID_*`. The service worker (`GET /sw.js`, cache `clinic-shell-v10`) shows the notification only when no visible `/bookings/` tab exists, so an open ticket buzzes once from the page. Fetch on `/admin` or `/livewire/` calls `registration.unregister()` and does not intercept. Filament `HEAD_START` (`filament/drop-patient-service-workers.blade.php`) unregisters every service worker on this origin and deletes `clinic-shell-*` caches so a leftover PWA from `/mups/` (or another path tenant) cannot own Live Queue Control. The patient site registers again on the next public visit.
- **SMS gateway** — optional HTTP driver; default `log` for local/tests; purposes gated by per-doctor `notify_channels` (see SmsService). Platform patient OTP uses the same gateway but **does not debit** `tenants.sms_balance`. Queue-approach alerts never send SMS.
- **Mail** — Laravel mailers for Filament password reset (configure `MAIL_*` in production)
- **No payment gateways** — intentionally removed for pay-at-chamber v1; online pre-payment is later-stage only and must not be suggested unless the owner asks
