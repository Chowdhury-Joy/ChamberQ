# Architecture Overview
Last Updated: 2026-08-07T01:50:29+0600

## Overview
Doctor Gemini is a multi-tenant SaaS for Bangladesh solo doctors and clinics. Each tenant gets a branded patient website, online serial booking, a live waiting-room queue (outdoor screen + staff control), a patient ticket/portal, and a Filament admin panel. Patients book a serial and pay at the chamber — there is no payment gateway. Online pre-payment is later-stage only: do not suggest or build it unless the owner explicitly asks. Sales CTAs on the central marketing site use WhatsApp (`wa.me`). SMS booking confirmations use a prepaid credit wallet topped up by Super Admin. Marketer partners earn commissions on setup and monthly subscription fees (manual bKash billing); Super Admin confirms doctor payments and marketer payouts.

## Getting Started
Prerequisites: PHP 8.2+, Composer, Node/npm (for Vite assets), SQLite (local) or MySQL/Postgres (production).

```bash
composer install
cp .env.example .env
php artisan key:generate
touch database/database.sqlite   # if using sqlite
php artisan migrate --seed
php artisan serve
```

Optional: `composer run dev` (server + queue + Vite + logs).

Key environment variables (names only): `APP_KEY`, `APP_URL`, `APP_TIMEZONE`, `CENTRAL_DOMAINS`, `DB_*`, `MAIL_*`, `MARKETING_WHATSAPP`, `MARKETING_PHONE`, `MARKETING_SOLO_*`, `MARKETING_CLINIC_*`, `MARKETING_SMS_CREDIT_PRICE`, `SMS_DRIVER`, `SMS_ENABLED`, `SMS_HTTP_URL`, `SMS_HTTP_API_KEY`, `SMS_HTTP_SENDER`.

Local URLs:
- Central marketing + Super Admin: `http://localhost/` and `http://localhost/admin`
- Marketer partner panel: `http://localhost/partner`
- Platform tenant (path tenancy): `http://localhost/solo/` (book at `/solo/book`, admin at `/solo/admin`)
- Custom domain tenant (optional): `http://solo.localhost/` and `http://solo.localhost/admin` (dev; production = doctor's own domain at root paths)

Tests: `php artisan test` (also CI via `.github/workflows/tests.yml`).

Scheduled tasks: `commissions:generate-monthly` runs on the 7th of each month (pending monthly commission rows for referred active tenants).

## Tech Stack
- PHP ^8.2, Laravel ^12, Filament ^4
- stancl/tenancy ^3.10 — hybrid tenancy: **path** on central domain (`/{tenant}/…`), **domain** for optional custom domains (root paths)
- mews/purifier ^3.4 (HTML sanitization for page builder)
- Livewire (via Filament)
- Blade views for patient site, booking wizard, ticket, portal, waiting-room screen
- Vite ^7 + Tailwind CSS ^4 (front-end build)
- PHPUnit ^11 for feature tests
- SQLite locally; MySQL/Postgres intended for production
- SMS: `log` driver (default) or `http` JSON POST gateway; prepaid wallet on `tenants.sms_balance`

## Key Components
- **Tenant + plan features** (`Tenant::hasFeature`, `Tenant::maxChambers`) — `plan_tier` `solo` | `clinic` with defaults; per-tenant `feature_flags` JSON can override. Solo defaults: `multiple_chambers` on (cap 5 via `SOLO_MAX_CHAMBERS`), no `lab_tests`, no `multiple_doctors`. Clinic defaults: all three on, unlimited chambers. `bangla_homepage` is a paid add-on flag. Browser tab icon via `Tenant::faviconHref()` — custom `favicon_url`, else shared `/icons/health-favicon.svg` (`Tenant::DEFAULT_FAVICON`).
- **Marketer commissions** — `Marketer` profile linked to central `User` (`role=marketer`). Referral via `?ref={code}`; discount codes via `?code=`. `CommissionService` snapshots list/due prices, creates pending setup/monthly commissions, confirms doctor payments → `owed`, marks marketer payouts → `paid`. Not commissionable: SMS packs. `EditTenant::afterSave()` reads every `wasChanged()` answer into locals **before** the re-pricing `save()`, because that second save re-syncs `$model->changes` — otherwise attaching a marketer and changing the plan in one edit silently skips the pending setup commission.
- **BookingService** — single write path for every booking (online wizard, Daily Roster walk-in, Live Queue walk-in). Creates serials under a row lock, enforces capacity/slot rules, attaches lab tests when the feature is enabled, normalises phones to `01…` via `BdPhone`, resolves or creates a `Patient` row (`patient_id` on the booking), and rejects a second live booking for the same **person** (`patient_id`) on the same bookable + date — with a legacy fallback for pre-backfill rows that still have `patient_id` null (same phone + same normalized name). Billing gate via `acceptsBookings()`.
- **PatientService** — `resolveForBooking()` find-or-create by phone + name; `patientsForPhone()` for the inline booking picker; `mergePatients()` and `moveBookingToPatient()` for staff corrections; fuzzy-name pair detection for backfill warnings.
- **Patient model** — tenant-scoped person record (name, phone, optional DOB or age+`age_recorded_at`, sex, allergies/conditions/medicines). `bookings()` / visit count / `last_visit_at`. Bookings keep denormalized `patient_name` + `patient_phone` for tickets and SMS.
- **Condition master list** (`conditions` table) — tenant-agnostic curated codes (~244 entries from `data/condition-list-draft.csv`): `code`, proper `name`, JSON `aliases` (English/Bangla/shorthand), optional `category` and `icd10_unverified`. Loaded via `php artisan conditions:load`. Free-text diagnoses (Stage 4) stay uncoded (`condition_id` null) and do not count toward research aggregates.
- **ConditionService** — `search()` matches name + aliases (min 3 chars), ranks doctor's frequent/recent picks higher via `condition_usages` (per tenant + doctor `use_count` / `last_used_at`). `resolveSelection()` returns coded or uncoded payload. `recordUsage()` bumps usage when a coded condition is picked on visit complete.
- **Condition picker API** — `GET /api/conditions/search?q=` (auth + `canViewConsultScreen`, throttled) returns ranked coded matches and `allow_free_text: true` for the Mark Completed diagnosis field.
- **Visit records** (`visit_records` table) — one optional row per completed booking: coded `condition_id` or `diagnosis_uncoded`, `advice`, `tests_advised`, `reports_seen`, `follow_up_date`, optional `voice_path`, `photo_path`, `voice_transcript`, `recorded_by` (doctor). Empty submissions create no row (honest “no notes recorded” state). `VisitRecordService::saveForCompletedBooking()` is the write path; calls `ConditionService::recordUsage()` for coded picks. Voice/photo alone count as clinical content.
- **Visit media** — `VisitMediaService` stores doctor voice notes under **`local` (private) disk** `visit-audio/{tenant_id}/` and prescription photos under `visit-photos/{tenant_id}/`, written with explicit `private` visibility. These are patient clinical records, so they must not sit on the `public` disk — that is symlinked into the web root and served straight by the web server, which would leave the authenticated controller real but bypassable by anyone holding the URL (random UUID filenames are obscurity, not access control: a public URL leaks via access logs, browser history and forwarded links, and can be neither revoked nor audited). `absolutePath()` is the only accessor and exists solely to stream through the controller — **do not add a URL accessor**. Laravel's `/storage/{path}` route serves the local disk but refuses private files (403). Enforced by `tests/Feature/ClinicalMediaPrivacyTest.php`, which asserts the property (not reachable over HTTP, not inside the web root) rather than the disk name. Doctors upload voice via in-modal MediaRecorder (`POST /api/visit-media/upload-voice`); playback and photo view at doctor-auth `GET /visit-records/{visitRecord}/voice` and `/photo` (staff forbidden). Transcript is manual/optional — never auto-sets coded diagnosis. No handwriting recognition on photos.
- **End-of-session catch-up** — `VisitRecordService::completedBookingsWithoutNotesToday()` counts today's completed bookings without clinical content (scoped to active session when shown on Consult Screen). Non-blocking amber banner on Consult Screen while a live session runs; header action lists patients to add notes. Ending a session from Live Queue Control warns doctors how many patients still lack notes.
- **Prescriptions** (`prescriptions` + `prescription_items`) — optional per visit record: medicines (brand uppercase, optional generic, dose/frequency/duration), advice, follow-up. **Print** at `GET /prescriptions/{prescription}/print` (doctor auth only) via browser print dialog (`tenant/prescriptions/print.blade.php`); reprint from Consult Screen past visits. Doctor profile fields `qualifications` + `registration_number` on `doctors`; warns if reg no missing before print.
- **Mark Completed with optional notes** — Daily Roster, Live Queue Control (doctor-run complete & call next), and Consult Screen show an optional Filament modal (`VisitNotesFormSchema`) for doctors only: diagnosis picker, advice, in-app prescription builder, **voice note** (browser record + upload), optional **voice transcript** (manual — no STT integration yet), **paper prescription photo** upload. Staff complete without modal. Never compulsory — blank form still completes the booking.
- **LiveSessionService** — start/end session, call next, call a *specific* patient out of turn (`callSpecificPatient()`), mark arrived (`in_chamber`), skip, complete; drives outdoor screen + Live Queue Control. `callSpecificPatient()` refuses while the current booking is `in_chamber` (a consult in progress is never interrupted) and returns a merely-`called` patient to `waiting` with `called_at` cleared and no skip strike, since being jumped is not their fault. `setAsCurrent()` clears `retry_queue_position` as it calls a patient, so a consumed retry slot cannot linger as a stale "back in queue after #N" hint. Queue mutations lock the `live_sessions` row with `lockForUpdate()` (mirroring booking's bookable lock) so two staff cannot both overwrite `current_booking_id`. Patient ticket ETA via `estimatedTimeForBooking()` using tenant `eta_model`: `schedule_guess` (default), `live_average`, or `live_steady` (falls back to schedule guess until completed consults exist for live modes). Conservative display knobs on the tenant: `estimated_time_buffer_minutes`, `first_n_patients`, `first_n_arrival_offset_minutes` (Branding Settings) pad the shown “come around” time so early-session patients are not told to arrive at the raw schedule slot. `LiveSession::bookings()` uses `HasManyByScheduleAndDate` so eager load matches `session_date` + `booking_date`. Daily Roster writes through `bringBookingToChamber()` / `completeBooking()` rather than updating `Booking` directly, so roster actions keep `called_at` / `in_chamber_at` / `completed_at` and the live session's `current_booking_id` in sync with the outdoor screen and patient ticket.
- **Outdoor screen** (`resources/views/tenant/screen.blade.php`) — shows chamber, doctor, and `ScheduleSession::screenLabel()` (session name + time window) so per-session serials are not confused on one TV. On each new call, announces per tenant `call_announce_mode`: chime only, voice, or chime then voice. Voice plays clear pre-recorded English WAVs from `public/audio/announce/number-{1..99}.wav` (“Number twelve”, Karen voice) — not browser SpeechSynthesis. Live Queue Control dispatches the same clip when staff taps Call / Start. One tap unlocks sound on the TV; mute stops playback. Chime file still from `call_audio_preset` / custom upload when chime is enabled.
- **Booking wizard** (`tenant.partials.booking-wizard` + shells `tenant.book` / `tenant.solo.book`) — client-side step machine. `rebuildFlow()` derives the visible steps from plan features and counts; the type step stays in the flow once shown (only `?doctor=` / `?test=` deep links set `state.typeLocked` and drop it), so step indices are stable and Back can return to it. Header shows dots plus a plain-language `Step :current of :total — <title>` label. Selection cards receive the clicked element (`this`) rather than the global `event`, and get a `.selected` state; lab-test checkboxes mirror it. Phone field is `type=tel` + `inputmode=numeric` + `autocomplete=tel`, placeholder `017XXXXXXXX`, and strips separators as the patient types (caret preserved) before the BD pattern check. When a known phone has existing household members, an inline **Who is this appointment for?** picker appears on the same identity step (not a new wizard step) via `GET /api/patients/by-phone`; choosing someone fills `patient_id` + name, **Someone new** leaves a fresh person. On phones (<640px) `.btn-group` is `position: sticky; bottom: 0` with `env(safe-area-inset-bottom)` padding, so Back/Continue stay reachable on long steps; Back keeps its natural width and the primary button takes the rest.
- **Chamber map link** — chambers store a pasted Google Maps share link in `map_url` (no latitude/longitude columns; a migration folded old coordinates into `?q=lat,lng` links). `Chamber::isGoogleMapsUrl()` accepts only Google hosts (`maps.app.goo.gl`, `goo.gl`, `maps.google.com`, or `google.<tld>` with a `/maps` path) and gates both the Filament form rule and rendering, so a pasted link cannot send patients to another host. `Chamber::googleMapsUrl()` returns the pasted link, else a Maps search on the chamber address, else null.
- **Vacation mode / slot blocks** — `SlotBlockService` is the single cancellation path, invoked from the `SlotBlock::created` hook so admin, console, and any future API behave identically. It cancels bookings on the blocked date excluding `cancelled` **and** `completed`, stamping `slot_block_id`, `cancelled_at`, and a reason. `CreateSlotBlock` only reports the resulting count — it runs no query of its own and renders no patient data; the escaped `filament.tenant-admin.slot-block-notify` modal on the list is where staff open per-patient WhatsApp links via `Booking::whatsappLink()` (which fixes the `88…` country code).
- **Admin panel guardrails** — Filament checks bulk actions against `deleteAny()`, and its "policy exists but method missing" path *allows*, so every tenant policy defines it explicitly: `ChamberPolicy` / `DoctorPolicy` return `false` (their rules are count-based — keep one chamber, keep a solo tenant's only doctor — and cannot hold across a selection authorized once), and those two tables carry no `DeleteBulkAction`; `LabTestPolicy` / `LabCollectionSlotPolicy` mirror `viewAny()`. Uniqueness rules mirror their DB indexes: tenant staff email is unique per `tenant_id`, marketer login email is unique among central accounts (`whereNull('tenant_id')`, which the `(tenant_id, email)` index cannot enforce), and the tenant slug is `unique` plus `notIn` the tenancy reserved path prefixes.
- **OperationalReportService** — day/week/month booking aggregates for staff.
- **SellerOverviewService** — Super Admin **Client Health** (`Filament/SuperAdmin/Pages/SellerOverview`): tenant-level usage signals only — quiet clients (days since last live session, booking drop vs own 4-week baseline, schedule set but never started), go-live funnel for recent signups (account → chambers → schedule → published site → first booking → first live session), SMS credit warnings (balance ≤ 5), overdue payments (setup unpaid or missing monthly vs last confirmed period). Never exposes patient names, diagnoses, prescriptions, or visit contents. All tenant-scoped aggregates use `withoutGlobalScope(TenantScope::class)` on central domain.
- **ResearchDataService** — Super Admin **Research data** (`Filament/SuperAdmin/Pages/ResearchData` at `/admin/research`): cross-tenant aggregate counts of **coded** diagnoses only (`visit_records.condition_id` set; uncoded free text excluded). Filters: date range, plan tier (`solo` | `clinic`) — no per-tenant or per-patient slicing. **K-anonymity:** `MIN_GROUP_SIZE` 10 — groups below 10 are suppressed and the UI prompts to widen filters; output never includes patient names, phones, or individual visit rows. Legal note on page references signup agreement (Appendix B in `patient-records-plan.md`).
- **SmsService** — confirm booking SMS after the booking transaction commits (booking never rolls back on SMS failure). Body leads with patient name and serial (e.g. `Rashed — serial 12`). Debits 1 prepaid credit **before** calling the gateway; refunds the credit if the gateway throws; skips send when the wallet is empty (`SmsMessage` row records every outcome). Path-tenant ticket links built from `config('app.url')`; custom-domain tenants use their Domain host. Custom call-audio uploads stored under `public` disk at `call-audio/{tenant_id}/`.
- **Tenant admin — Patients** (`Filament/TenantAdmin/Resources/Patients`) — searchable patient list; header action to join two records; per-row action to move a visit to another patient. Daily Roster and Live Queue Control walk-in modals use the same household picker as the public wizard.
- **Tenant admin — Live Queue Control** (`Filament/TenantAdmin/Pages/LiveQueueControl` + `resources/views/filament/tenant-admin/pages/live-queue-control.blade.php`) — the queue runner's operating screen. Auto-selects today's session when there is exactly one, otherwise offers a picker (dropdown, or session cards before a choice is made). A summary strip reads waiting / seen / no-show / average consult length (measured from today's completed `in_chamber_at`→`completed_at` spans, falling back to `LiveSession::avgConsultationMinutes()`) / projected finish time, from the `queueStats` computed property. The current-call card shows a display-size serial, patient name, a client-side elapsed timer (corrected for server/browser clock skew, turning red past `LiveSession::callTimeoutSeconds()`), and one full-width primary action — Patient arrived / Complete & call next / Call #N, or a disabled "No one waiting". Skip is labelled with its consequence ("No response — skip (1 of 2)" → "mark no-show" on the last strike). Paused sessions show the captured reason and `LiveSession::pauseEndsAt()` with an in-card Resume; delayed, completed and cancelled sessions each get their own card body. The five session-lifecycle actions (Mark Late, Pause, Resume, Cancel, End) sit in a single **Session actions** `ActionGroup`, leaving **New Walk-In** as the only standalone header action. The queue table ranks `called` first (then `in_chamber`, `waiting`, `skipped`, `completed`, `no_show`, `cancelled`), highlights the current row via `recordClasses`, offers per-row **Call now** for out-of-turn calls (hidden while someone is in the chamber) and **Reinstate** for `no_show`, and polls every 3s. Per-patient success toasts on call-next / arrived were deliberately removed as noise; the skip toast names the patient and states what happens next. **All page CSS is a plain-CSS `<style>` block using `lqc-`-prefixed classes** — this panel has no custom Filament theme build, so general Tailwind utilities (`grid-cols-3`, `gap-6`, `text-sm`, `w-full`, …) are absent from the shipped `public/css/filament/filament/app.css` and do nothing here.
- **Web page builder** — Filament WebPages resource; solo template sections under `resources/views/tenant/solo/`; clinic/shared sections under `resources/views/tenant/sections/`. SafeUrl allowlist for links, then `tenant_safe_href()` so relative CTAs (e.g. `/book`) get the path-tenant prefix on central hosts. Solo shell (`tenant/solo/webpage.blade.php`) owns shared CTAs, section padding (`.solo-section` / `.solo-section-hero`), fade-ins, and sticky header; section blades keep Figma-matched Tailwind type sizes (including display line-heights from the design file). Solo hero headline is a textarea: line breaks render as a two-line name on mobile (`whitespace-pre-line`) and collapse to one line from `sm` up. Clinic shell (`tenant/webpage.blade.php`) and clinic book/ticket/portal shells still use an interim solo-style visual language (DM Sans + Instrument Serif, pill `.solo-cta` / `.solo-cta-outline`, white sticky header and footer) with a wide facility-banner hero and multi-doctor / multi-branch / lab-oriented sections (`doctor_grid`, `about_facility`, `location_hours` with optional `locations[]`, `service_matrix`, shared FAQ/conditions/testimonials/video). **Clinic design direction (approved 2026-08-06):** future clinic homepage work follows `public/previews/clireo-homepage.html` (Clireo/CBPH reference), not this interim shell. `css/card-grid.css` is linked so `<x-card-grid>` sections lay out correctly on the Tailwind CDN patient site. **Locked:** do not change solo homepage UI or Book Appointment CTA wiring/styling unless the owner says `update patient homepage` / `change patient homepage` (see `.cursor/rules/patient-homepage-lock.mdc`).
- **Roles** — Super Admin (central `/admin`); Marketer (central `/partner`); tenant `admin` / `doctor` / `staff` with capability helpers (`canManageOps`, `canManageContent`, `canManageQueue`, `canViewConsultScreen`, `canViewVisitNotes`, `canRecordVisitNotes`, `canOperateQueueControls`, `canAccessLiveQueueControl`, etc.). Queue management and Daily Roster are **doctor or staff only** — not account owner (`admin`). Live Queue Control is only for the configured queue runner (`canAccessLiveQueueControl`). Consult Screen and visit notes/prescriptions are doctors only (`canViewConsultScreen`, `canViewVisitNotes`, `canRecordVisitNotes`). Visit notes never appear on patient ticket or portal.
- **Tenant queue runner** — `tenants.queue_runner`: `staff` (default) or `doctor`. Owner flips in Branding Settings → Live Queue Settings. Staff-run: staff operate Live Queue Control; doctor Consult Screen auto-follows. Doctor-run: doctor operates queue (including optional controls on Consult Screen); staff see Daily Roster without call/complete actions and cannot open Live Queue Control. `Tenant::queueRunner()` is the *configured* choice; `Tenant::effectiveQueueRunner()` is that choice checked against reality and is what `User::canOperateQueueControls()` consults. When the configured party has no user in this practice, controls fall back to the other party — a solo doctor with no staff was otherwise locked out of their own chamber by the staff default, and only an admin can change the setting. Exclusivity is preserved: the fallback only fires when the configured party has nobody, so two parties are never live at once, and the account owner never gains controls through it (`canManageQueue()` still excludes admin). Role presence is memoised per request on the Tenant instance.
- **TenantUserBootstrapService** — `ensureDoctorLogin()` / `hasDoctorLogin()`; Super Admin tenant create requires `initial_doctor_email` and creates a doctor user so solo practices are not owner-only.
- **Tenant admin — Consult Screen** (`Filament/TenantAdmin/Pages/ConsultScreen`) — auto-follows today's active `live_sessions.current_booking_id`; shows patient demographics, visit count / last seen, clinical warnings, last visit diagnosis/advice/voice/photo/transcript when notes exist, honest “N previous visits · no notes recorded” when not. Past visits list with reprint prescription links, voice playback, and prescription photo links. Catch-up banner when today's session is active and completed patients lack notes. Never shows serial, chamber, time, or payment. Solo hides doctor column and lab orders; clinic shows doctor on past visits. Polls every 3s. Doctor-run doctors get call/arrived/complete-with-notes actions when they operate the queue.
- **Panel home URLs** — `Panel::getUrl()` resolves a `home` route Filament never registers, so it falls back to `url($panel->getPath())`. That is accidentally right for `admin` / `partner` and wrong for the path panel, whose path is the pattern `{tenant}/admin`. `FilamentPanelUrl::home()` resolves the panel's `pages.dashboard` route by name (via Filament's `generateRouteName()`, which keeps the domain segment multi-domain panels add) and supplies the tenant slug from the route or initialized tenancy. `FilamentLoginResponse` is bound to Filament's `LoginResponse` contract for **all** panels so post-login redirects use it; the path panel additionally sets `homeUrl()` so the topbar/sidebar logo link is right.
- **Sessions never expire on idle** — `SESSION_LIFETIME` is 525,600 minutes (one year, the practical ceiling since browsers cap cookie lifetime near 400 days) and `config/session.php` carries that as its default too, so a missing env var cannot reintroduce a timeout. The one value governs the cookie's `Max-Age`, file-session validity, and the GC deletion threshold. `SESSION_EXPIRE_ON_CLOSE=false` and `AUTH_PASSWORD_TIMEOUT` is a year, so no re-authentication prompts either. Deliberate owner decision for a single-operator chamber panel — revisit before multi-staff production use (see `decisions.md` 2026-08-05T21:01:25+0600). **Locked:** do not shorten these or restore the framework's 120-minute default unless the owner says `change session expiry` / `restore session timeout` (`.cursor/rules/session-expiry-lock.mdc`, `CLAUDE.md`).
- **Sessions across panels** — all three panels share one host and therefore one session cookie, and Filament rotates the CSRF token via `session()->regenerate()` on every login. A panel page left open while you sign in elsewhere therefore commits a dead token and Livewire returns 419. `AppServiceProvider` registers a global `panels::body.end` hook that reloads the page on 419 **for guests only** — signed-in pages keep Livewire's own prompt so a half-finished page-builder or walk-in form is never discarded silently. A 419 is not by itself evidence of a tenancy-middleware fault: verify with a real Livewire commit before touching the middleware stack (see `bug_history.md` 2026-08-05T20:19:38+0600).
- **Marketing site** — central `config/marketing.php` plans/pricing/WhatsApp CTAs; Blade home at `resources/views/marketing/home.blade.php`; session capture for referral/discount params.
- **Card grid standard** — one column rule for every card collection (marketing, tenant sections, admin stat widgets): mobile 1, tablet 2 (≥640px), desktop (≥1024px / Tailwind `lg`) 2 when the count is 2 or 4 and otherwise 3. Blade uses `<x-card-grid :count="…">`; Filament stat widgets use the `UsesCardGridColumns` trait; both resolve through `App\Support\CardGrid`. Tenant patient sites use Tailwind CDN (not Vite), so those layouts must `<link>` `css/card-grid.css` or the grid classes do nothing. Solo `condition_library` matches Figma “Conditions I Treat”: equal treatment cards in a row; feature pills under Including stay a vertical list.
- **Patient ticket** (`tenant.partials.ticket-body` + `tenant.ticket` / `tenant.solo.ticket`) — live queue poll, WhatsApp/copy share, Maps link from `Chamber::googleMapsUrl()` (pasted `map_url`, else an address search). A fixed **serial strip** (`#serialStrip`) fades in once the big serial scrolls past, keeping the patient's serial and the number now being called on screen while they read the map/prep sections; it turns green while `is_called`. Each shell sets the strip's `top` to its own header offset (0 on `tenant.ticket`, which has no navbar, 68px/95px on `tenant.solo.ticket`) and the shared JS reads that live `rect.top`, so no breakpoint is duplicated in script. Strip carries `no-print` and `aria-hidden` (the `.live-queue` region already announces changes). **Print** and **Save as PDF** both open the browser print dialog (`window.print()`); `@media print` hides nav/share/live-queue chrome and keeps serial + visit details + a footer with the ticket URL. No server-side PDF library — patients pick “Save as PDF” in the print destination (phones and desktops).

## Data Flow
1. **Sales:** Visitor hits central `/` (optional `?ref=` / `?code=`) → WhatsApp CTA includes referral context → Super Admin creates tenant, attaches marketer/discount, snapshots pricing → pending setup commission.
2. **Billing:** Super Admin confirms doctor setup/monthly payment (manual bKash) → commission moves to `owed` → monthly cron creates pending rows → Super Admin marks marketer payout paid. **Client Health** (`/admin/seller-overview`) surfaces who went quiet, where new signups stall, SMS wallets at risk, and overdue accounts — counts only, never patient clinical data. **Research data** (`/admin/research`) shows anonymous coded-diagnosis aggregates across all practices with k-anonymity (minimum group size 10).
3. **Patient book:** Tenant site → `/book` wizard (each step labelled `Step n of N`, inline household picker on the phone step when the number is known, Back/Continue sticky to the bottom on phones) → `GET /api/bookings/availability` + `GET /api/patients/by-phone` → `POST /api/bookings` (optional `patient_id`) → `BookingService` creates booking + patient link inside a DB transaction with `lockForUpdate()` on the bookable (and doctor row when `slot_cap_mode` is `per_doctor_chamber`) → after commit, `SmsService` debits wallet and sends confirmation naming the patient → redirect to `/bookings/{uuid}` ticket (share via WhatsApp/copy, or Print / Save as PDF via the browser print dialog).
4. **Clinic day:** Staff or doctor (per `queue_runner`) open Live Queue Control → start session → call patients → Patient arrived (`in_chamber`) → complete (doctors get optional visit-notes modal with voice/photo; staff complete without notes). Patients can also be called out of turn from their table row, and a no-response skip is taken from the current-call card with its consequence spelled out on the button. Doctor Consult Screen auto-follows `current_booking_id` for clinical context including last visit notes and catch-up banner for patients completed without notes. End session warns doctors if notes are still missing. Daily Roster is a second entry point (walk-ins, roster view); call/complete actions only for the queue runner. Both screens route through `LiveSessionService`, so outdoor screen and ticket stay in sync. Outdoor TV polls `/api/screen/{session}/{date}`. Ticket page polls `/api/queue/{booking}` — neither exposes visit notes or media paths.
5. **Lookup:** Patient opens `/portal`, enters phone → exact-match booking list (throttled).
6. **Content:** Admin structures WebPages; staff edits text/images; public `/{slug?}` renders tenant site.
7. **Labs (clinic tier / flag):** Patient can add lab tests + collection slot during booking; ops manage LabTests + LabCollectionSlots in admin.
